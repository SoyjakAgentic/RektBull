Pay per call with x402

      
For bots and agents without an account: the paid runs take x402, USDC on Base. You're charged only when the run succeeds; bad input is refused before any charge.

      

        
01
Call it
Without payment, a paid endpoint answers 402 with what to pay, to whom, on which network.

        
02
Sign the payment
Your x402 client signs a USDC transfer authorization and retries with it in the X-PAYMENT header.

        
03
Get the result
RektBull runs the check, then settles the payment; the transaction comes back in X-PAYMENT-RESPONSE. A run that fails is never settled.

      


# 1. no payment: 402 and the terms
curl -X POST /v1/tokens/quick-check \
  -H 'content-type: application/json' \
  -d '{"chain":"base","token_address":"0x…"}'
# → 402 {"x402Version":1,"accepts":[{"scheme":"exact","network":"base","maxAmountRequired":"250000",…}]}

# 2. the same call with X-PAYMENT: your x402 client does this for you

Rules we keep

      
    
        
  • Every fact names its source, and a check that couldn't run says why. No AI fills a gap with a guess.
    • 
        
  • Never your keys. RektBull prepares transactions; the user's wallet signs them. Nothing here asks for a seed phrase or a private key, ever.
    • 
        
  • Charged only for work delivered. Input is checked before charging; a run that fails is refunded or never settled.
    • 
        
  • Not financial advice. Findings are facts with sources. Please show them that way: don't present a token, dapp or campaign as "safe" because RektBull found nothing.
    • 
        
  • Fair use. 120 API requests a minute per IP address, plus the daily allowances shown. Cached data is refreshed every few minutes; there's no need to poll faster.
